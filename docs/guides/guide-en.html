1. What you need

  • OBS Studio on a computer (Windows, macOS, Linux) — the program that sends the video. Free, obsproject.com.
  • A VPS running Ubuntu (4 GB of RAM is plenty for one broadcast) and a domain with a DNS A record pointing at the VPS.
  • The Livecast repository, and five minutes for the initial install.

Install (once, from a terminal)

git clone https://github.com/sdagostino777/livecast.git

cd livecast && cp .deploy.env.example .deploy.env

Fill in .deploy.env with your server address, then:

APP_DOMAIN=live.yourdomain.com bash infra/scripts/deploy.sh --provision

The script installs everything: the media server (MediaMTX), the encoder (FFmpeg), the services that restart themselves after a failure, nginx, the free HTTPS certificate, and the admin account. It prints the admin password once: store it somewhere safe.

Right after install, open https://live.yourdomain.com/admin, sign in as admin and change the password immediately (gear → Sicurezza).

4. Going live with OBS

In the panel press Mostra credenziali (show credentials) and copy the full server URL. In OBS → Settings → Stream:

OBS Studio — Settings → Stream
ServiceCustom…
Serverrtmp://live.yourdomain.com:1935/live?user=publisher&pass=••••••
Stream key(empty)

Press Start streaming in OBS: the panel turns to In onda within seconds. Copy the broadcast link and share it. Viewers see the poster and a play button — play and pause, nothing more.

4. Before play: the event poster and the play button.

5. Viewers, CDN and the unexpected

How many viewers does the VPS handle? Up to ~500 simultaneous the VPS alone is enough. Beyond that you need a CDN: in the panel → Configurazione enter the CDN URL and check that the LED next to it turns green. With a CDN viewers load video from the edge and the VPS stays light.

5. Green LEDs = active connections. “In uso: backup” = the second encoder took over.

When things break

  • OBS disconnects → the encoder restarts by itself within seconds; when OBS reconnects the video returns.
  • The primary encoder dies → if a second encoder is connected to the backup URL, the panel shows “In uso: backup” and the broadcast continues.
  • The server dies → no software on that server can save it: you need a standby VPS with the data (the DATA_DIR folder) and DNS re-pointed. That is the emergency plan to prepare for important events.
