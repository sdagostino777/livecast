1. What you need

  • an external streaming program on a computer (Windows, macOS, Linux) — the program that sends the video. Free ones exist for all three; this guide does not require any specific one.
  • A VPS running Ubuntu (4 GB of RAM is plenty for one broadcast) and a domain with a DNS A record pointing at the VPS.
  • The Livecast repository, and five minutes for the initial install.

1. Download it (once)

On GitHub: green Code → Download ZIP (fine from a phone too — upload the ZIP to the server). From a terminal:

curl -L https://github.com/sdagostino777/livecast/archive/refs/heads/main.tar.gz -o livecast.tgz

tar xzf livecast.tgz && cd livecast-main

2. One command installs everything

In your server's terminal (Hostinger → VPS → Terminal, as root), inside the folder you just unpacked, type:

bash install.sh live.yourdomain.com

It installs the media server, the encoder, the services that restart themselves after a failure, free HTTPS, the firewall and the admin account. Nothing else: an external encoder is not mandatory and no file needs editing by hand.

3. First login: open https://live.yourdomain.com/admin, user admin, password admin. The panel forces you to change it immediately: pick at least 12 characters and you are in.

2. First login and creating a broadcast

Open the panel link and sign in. Top right you will find three small icons for the theme (light, dark, system) and the account button (the person icon), which opens Impostazioni (settings) and Esci (sign out).

1. Sign-in screen.

In the Diretta box write the title — for example Congresso Internazionale 2027 — Bologna — choose Video or Audio only, add the event image if you want (and tick “Show the event name over the image” to print the title on it). There is nothing to save: every change applies at once and the preview follows while you type. When you are ready press ● ONLINE.

The broadcast link sits right above, with Copia link: you can already share it, because whoever opens it sees the event name and image even before you go live. After the show, Nuovo evento creates the next event with a new link.

2. The panel while on air: state, link, preview and the camera feed.

No image at hand? The system generates one from the event title on a gradient background (deep navy, petrol, indigo…). Replace it whenever you like with “Carica immagine”.

3. Settings (from the account menu)

Pick Impostazioni from the account button. The page collects what belongs to the service, not to the event:

  • Configurazione: the service name and logo — yours, and shown to whoever receives the link; the logo also becomes the browser tab icon. Below: public URL, the CDN if you use one, and the ingest host/port, with Verifica CDN and Salva.
  • Sicurezza: your password and the recovery codes.
  • Utenti (admin only): who else may broadcast.
  • Manutenzione: closes broadcasts left hanging and shows the logs.

The theme is not here: the three small icons top right switch it instantly. The event image and the “Show the event name over the image” checkbox live in the Diretta box, next to the title.

3. Settings: name, logo, public URL, CDN and ingest; then security, users, maintenance.

4. Going live

Two ways, no mandatory software. In the panel, under the broadcast, you find Collega camera and Collega schermo preview and connect the browser to the server — nobody sees you until you press ● ONLINE. The page must stay open during the broadcast — reloading it stops the transmission. For long events an external encoder is the safer choice (it reconnects by itself): here is how to configure it.

In the panel press Mostra credenziali (show credentials) and copy the full server URL. In the encoder → Settings → Stream:

external encoder — Settings → Stream
ServiceCustom…
Serverrtmp://live.yourdomain.com:1935/live?user=publisher&pass=••••••
Stream key(empty)

Press Start streaming in the encoder: the panel turns to In onda within seconds and the time on air counter starts. Next to the state you can read how many people are connected right now. Copy the link and share it: WhatsApp already shows a preview with the event name and image. Viewers see the poster and a play button — play and pause, nothing more.

4. Before play: the event name and image, then just play.

6. Forgot your password? Recovery codes

When you set (or reset) the password, the system generates 8 recovery codes and shows them once. Copy or print them: they are the only way back in on your own if you forget the password.

38247-FA538 · 890E4-A0BB6 · 28537-304BB · AA636-54122

D13F4-A3352 · F8FBC-E02C8 · C8454-86EE7 · EB5DC-70BEF

This is what they look like. Yours will differ: save yours.

  • On the sign-in page press Password dimenticata?.
  • Enter the user, one code and the new password (at least 12 characters).
  • The password changes and every session is closed. Each code works once.
  • In Settings → Sicurezza you can see how many codes remain and regenerate them (current password required: the old ones stop working).

Lost the codes too? Whoever administers the server resets the password from the command line. The command also prints 8 new codes:

cd /srv/livecast/app

node --env-file=.env apps/api/dist/cli.js reset-password --username admin --password admin

In the database the codes are stored only as a cryptographic hash: nobody — not even the server administrator — can read the plaintext code back.

7. Viewers, CDN and the unexpected

How many viewers does the VPS handle? Up to ~500 simultaneous the VPS alone is enough. Beyond that you need a CDN: in the panel → Configurazione enter the CDN URL and check that the LED next to it turns green. With a CDN viewers load video from the edge and the VPS stays light.

5. On air: the blinking dot and the STOP button stay visible.

When things break

  • the encoder disconnects → the pipeline restarts by itself within seconds; when the encoder reconnects the video returns.
  • The primary encoder dies → if a second encoder is connected to the backup URL, the panel shows “In uso: backup” and the broadcast continues.
  • The server dies → no software on that server can save it: you need a standby VPS with the data (the DATA_DIR folder) and DNS re-pointed. That is the emergency plan to prepare for important events.
